## 金融论证中确定的规则

1. 第20日草案下甲超出20万元只在第40、41日，第42日第3批货款到账后归零。2.0 的31万元至第120日与此不匹配。
2. 机制收窄为"批次回款衔接的专项提款安排"，金融工具对应现有订单融资、保理、应收账款质押和受托支付，不作为新产品。
3. 专项只能由甲使用，只用于指定批次的采购付款和该批成员尾款；不循环。
4. 提用顺序：现金 → 一般额度剩余 → 专项。日终回笼先还专项。
5. 引擎内提款条件：窗口内（开放日≤当日≤截止日，且早于到期日）、无欠息、未用满、还款来源批次已验收且其合同付款日早于专项到期日、按设定核对逾期（none / internal / chain）。演示默认 internal。
6. 下游逾期（chain）不作自动拦截，改为复核提示：正常情景中误拦22.8%的匹配路径。
7. 到期后仍有专项本金：记逾期天数；默认冻结甲一般额度新提款（模型中未改变结果）。
8. 额度区间：下限为确定性待筹峰值，上限为 min(还款来源应收, 用途支出)。不输出单一建议额度。

## 页面与流程实现（2026-11-09）

- `workflow.ts`：`execConfig()` 统一构造执行配置；专项只在其依据规则（`ruleHash`）为当前有效规则时进入执行投影，草案未生效前不影响原规则执行。
- 新增 `financingPlan()`、`confirmReceivable()`、`reviewSignals()`、`arrangements()`、`trancheOf()`、`extraLimitDays()`；`submitBank()` 增加 `structure` 参数（默认 GENERAL，与 2.0 调用兼容）；`bankDecision()` 增加 `terms` 参数；`acknowledgeBank()` 对专项写入 `state.tranche`。
- 防重复融资：同一业务依据（规则摘要与草案摘要）下，甲只能有一项未被拒绝的融资申请；专项到期前不能再申请新的融资。
- 尾款提用最初只受到期日限制，页面走查时发现会在提款窗口外动用专项，改为与采购相同的窗口限制（TS 与 Python 同步）。改动后匹配情景中甲平均利息变化不到0.02元，基准情景变化约0.03元，其他指标不变。
- `study.ts` 新增 `financingStudy()`，计算线程按 `request.kind` 分派；页面对照与 Python 研究使用同一组安排（`check-financing-study.mjs` 核对129项）。
- 本地存储改为 `bianmao.v3`、`schema: 3`，不读取 2.0 记录。
- 新增快捷场景 `?scene=financing`（第20日草案，直接打开金融转译，融资结构默认为批次专项）。
