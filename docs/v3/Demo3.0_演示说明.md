# Demo 3.0 演示说明（面向评委）

编写：ClawsGO Science Agent，2026-11-10。

打开方式：用 Edge 或 Chrome 直接打开 `demo.html`，或访问部署后的站点。页面不联网也能运行。顶部始终显示"竞赛原型 · 模拟业务与银行回执"。演示前点"重置演示"清除本机记录。

全程约8分钟。前两幕沿用 2.0，第三幕是 3.0 新增内容。

## 第一幕（约1分钟）：一项账期提议造成多大的缺口

打开 `?scene=recalculate`，进入"变化重算"。

- 第20日，乙提出把第三至第五批账期从5日改为15日。
- 讲解三个数：甲维持原采购日历需要的资金从17.064万元升到30.672万元；对照20万元额度，待筹10.672万元；额度不变时，第五批采购从第40日推迟到第42日，回款从第65日推迟到第68日。

## 第二幕（约1分钟）：缺口的形态

打开 `?scene=financing`，页面直接进入"金融转译与核查"，融资结构默认为"批次专项提款"。

看"融资支持方案说明"表：

- **缺口形态**：只在第40、41日超出20万元。
- **还款来源**：第3批第27日已验收，乙应于第42日付甲13.608万元。
- 讲解要点：这是一笔两天的过桥需要，而且有一笔已经验收的应收可以对应。2.0 演示中把甲的总额度提到31万元、用到第120日，承诺期远长于需要。

## 第三幕（约4分钟）：在现有产品框架内，怎样更贴合这笔需要

1. **额度区间与条件**。方案说明给出下限10.672万元、上限13.608万元（不超过还款来源应收）、第21日起可提、第50日截止、第62日到期。下方"提款前条件"逐项显示状态。说明：额度、期限和产品形式由银行决定，平台只提供依据。
2. **安排对照（确定性）**。表中四行：原账期（Rule-V1）第五批第40日、甲利息226.58元；草案现有额度第42日、532.34元；一般额度提至31万元与专项13.608万元都在第40日，利息同为565.34元，额外承诺分别为1089和285.8万元·日。
3. **情景对照**。点"在第20日历史匹配情景中对照"，约10—20秒得到3969条路径的结果：按计划采购比例原账期89.9%、草案原额度0%、一般提额100%、专项98.2%；专项有1.8%的路径因第3批未按时验收而不能提用。**同时指出代价**：两种融资都让甲的利息从约599元升到约665元，借款峰值升到约30.7万元。
4. **乙确认应付**。演示角色切换为"加工企业乙"，点"确认第3批应付"，条件表中该项变为"满足"。说明：这只证明还款来源，乙不因此为甲的借款担保。
5. **甲提交**。切回"合作组织甲"，点"提交专项提款方案"。可再点一次，事项不会重复；改选"一般额度调整"再提交会被拒绝，防止同一缺口重复融资。
6. **银行模拟审批**。切换"客户经理"。专项额度填14，点批准，系统提示不能超过13.608万元；改回13.608，到期日填40，提示须晚于还款来源付款日；改回62后填写意见并批准，再回填办理回执。说明：只有客户经理能作出结论，经营角色看不到这些输入框。
7. **合同确认与执行**。此时草案仍"待确认"，专项不进入执行投影。切回甲，到"变化重算"确认草案并生效，再回到"金融转译与核查"。"按获批条件执行"表显示：第五批第42日→第40日，回款第68日→第65日，第40日提用10.672万元、第42日归还。
8. **（可选）凭证**。"履约台账"中把观察日推进到D42并载入记录，可看到"专项提款（受托支付至采购收款方）"和"专项本金归还（回笼账户日终扣划）"两条模拟凭证。

## 第四幕（约1.5分钟）：风险并没有消失

打开 `?scene=financing-stress`（下游持续拖欠），按第三幕第4—7步快速办理一遍。

- "按获批条件执行与复核提示"给出：下游回款逾期；专项到期日第62日仍有本金3.5万元。
- 说明：融资让第五批照常采购，但下游一直不付款时，甲的期末借款从8.64万元增加到23.5万元，专项还会逾期。专项和一般提额在这个情景里的敞口相同。
- 客户经理点"依据提示发起风险核查"，形成核查事项；提示本身不改变额度和借款。

## 回答评委提问的要点

- **和工行现有产品有什么区别？** 金融工具不新，银行可以用订单融资、保理或流动资金贷款分笔办理。新增的是由多主体、多批次的联合台账确定"哪笔已形成的应收对应哪笔待启动的采购"，把提款条件写成可核对的履约节点，并在同一组情景下比较安排的改善和代价。
- **为什么不直接给出建议额度？** 平台算的是这组交易的资金需要。合理授信额度要看借款人整体经营，审批额度由银行决定。页面只给区间和每种取值的模拟表现。
- **数字是不是真实效果？** 不是。情景分布是演示假设，所有比例都是模型在这些假设下的结果，不是违约率，也不是已观察到的融资效果。
- **下游违约怎么办？** 专项挡不住。把下游逾期设为自动拦截，在正常情景中会误拦约23%的路径，所以作为提示交给客户经理。
- **边民、互助组能借吗？** 本安排只适用于可作借款人的合作组织甲。互助组一般不具法人资格；边民个人经营贷适用个人贷款办法，不在本安排内。

## 可能的问题

- 情景对照运行约10—20秒，期间不要切换页面。
- 手机宽度下新增的宽表格需要在表格内左右滑动。
- 浏览器会记住上次演示进度；快捷场景链接每次都会重新载入案例。
