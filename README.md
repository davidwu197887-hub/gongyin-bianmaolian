# 工银边贸智链

边民互市经营协同与融资需求联动平台。演示版本 3.0（第二阶段研发），2026年11月。

3.0 在 2.0 基础上增加"批次专项提款安排"的模拟：由联合台账识别已验收批次的应收能否覆盖待启动批次的采购，形成方案说明、提款条件和复核提示，并在同一组情景下与原额度、一般额度调整对照。论证与证据边界见 `docs/v3/授信模式设计与创新性对照.md`。2.0 的八个工作区、贯穿案例与全部基准结果保持不变。

## 打开演示

直接用 Chrome 或 Edge 打开 `demo.html`。图表、业务计算与情景样本均包含在文件内，无需联网。`dist/index.html` 与 `demo.html` 内容一致，可用于静态网站托管。

页面中的合同、参与记录、额度、银行处理与支付回执均为模拟资料。角色切换用于展示各方职责，真实身份认证和银行连接按实际接入条件建设。浏览器在本机保存演示状态；“重置演示”清除本轮模拟记录。

## 主要工作区

| 工作区 | 使用内容 |
| --- | --- |
| 联合测算 | 五批采购、加工和销售回款，分别计算甲乙资金需要与额度受限后的执行投影 |
| 方案对比 | 比较价格、账期、贸易预付款及两端分批安排；运行未来情景和历史匹配分析 |
| 共同规则 | 记录甲乙按责确认，将共同规则与银行条件分别保存 |
| 履约台账 | 分别登记、核验验收事实、支付回执和银行日终记录 |
| 变化重算 | 对尚未到期批次提出账期草案，比较资金、采购、回款和清偿时间 |
| 金融转译与核查 | 分别提交融资需求和风险核查，展示补充材料、银行意见、办理结果及回执回填。3.0 增加融资支持方案说明、提款条件、安排对照、按获批条件执行与复核提示 |
| 成员明白账 | 按本人批次核对预付、应付、实付及相关依据，处理成员核对申请 |
| 版本与留痕 | 查看有效规则、草案、历史版本与连续操作记录，导出业务档案 |

## 建议演示顺序

1. 查看联合测算及三组谈判候选，观察同一付款条件对双方的不同影响。
2. 点击首页“载入第20日模拟案例”，载入案例合同、甲乙确认、履约材料、支付回执与日终对账。
3. 在“变化重算”选择第三至第五批，提出15日账期草案。甲维持原计划的资金需要由17.064万元变为30.672万元；对照20万元额度，待筹峰值为10.672万元。
4. 查看第五批采购在额度约束下由第40日顺延至第42日，成品回款由第65日后移至第68日，以及借款清偿时间的相应变化。
5. 将需求提交银行。切换客户经理视图，填写核查意见并要求补充材料；切换经营主体补充，再由客户经理反馈处理结果。
6. 融资批准和合同确认分别操作。获批条件回执在下一日及之后进入执行投影，既有历史保留；经营主体完成必要确认后，再使用新的合同规则。
7. 在新增融资金额为0的情况下，单独发起“风险核查”。该入口用于跟踪原有融资、回款或偿付安排。
8. 在履约台账中只核验第8日首批验收，成员端显示100元应付尾款；独立核验相应支付回执后，才显示已支付。

快捷场景：`?scene=compare`、`?scene=recalculate`、`?scene=translate`、`?scene=risk`；3.0 新增 `?scene=financing`（第20日草案，融资结构默认批次专项）与 `?scene=financing-stress`（同上，叠加下游持续拖欠）。后面三种场景经正式业务函数载入模拟确认与历史记录。指定快捷场景后，刷新重新载入相应案例。

## 计算口径

- 五批数量为32、44、36、48、40吨，合计200吨。
- 规划口径识别维持采购日历所需资金；执行口径受到双方资金、额度、利息及生产资源约束。
- 自有资金包含付息准备金，经营现金与准备金分别记录。利息按实际本金逐日计提，在结息或清偿节点支付。
- 同一笔内部付款同时记入双方台账；同步峰值按同一时点合计，成员商品货款独立保留依据。
- 已验收但尚未付清的货款、成员尾款，以及尚未采购或完成加工的数量持续保留。
- 本组业务台账与企业整体财务资料分别处理。银行还需核验其他收支、全口径债务及实际可用资金。

## 情景与历史匹配

情景数据使用基准、温和、严峻三组假设，包含具有持续性的口岸与下游状态，以及单批额外延迟。基准样本12000条，温和、严峻各6000条。样本输入与参考模型一同提供，便于重复验证。

浏览器内的独立计算线程运行同一现金流模型。第20日滚动分析逐项比对截至该日各处理阶段的资金、数量和收付款历史，保留一致路径后继续计算；草案采用同一批保留路径。默认基准保留3969条。数量扰动选项对各批施加±1%扰动并保持总量200吨，此时历史兼容样本数可能减少。

P90、P95和覆盖比例为所声明情景下的条件统计。界面保留参数和结果版本，参数变化后提示重新计算。模型结论需要通过真实样本进一步校准和检验。

## 本地开发与验证

Node.js 22.12及以上（2026-11-09 实测 22.22.2 / npm 10.9.7）：

```sh
npm ci
npm run typecheck        # TypeScript 类型检查
npm test                 # 30条 Python 参考路径对照 + 33项业务流程检查 + 29项批次专项流程与全情景不变量
npm run test:financing   # 同上29项，另加浏览器计算线程的融资安排情景统计与 Python 对照（129项）
npm run test:study       # 12000条情景与第20日历史匹配
npm run test:invariants  # 资金守恒、批次、额度约束与贯穿案例关键数值
npm run build            # 生成单文件 dist/index.html 与 demo.html
npm run test:e2e         # 浏览器测试（基于 dist/，默认 Windows Edge）
npm run preview          # 本地预览构建产物 http://127.0.0.1:4173/
```

`npm run build` 先把计算线程打包进 `src/workerCode.ts`，再生成单文件 HTML。`index.html` 是已构建的单文件入口，`npm run dev` 打开的是这份构建结果；修改源码后请重新 `npm run build` 再预览。

浏览器测试默认调用 Windows Edge。其他平台设置 `BROWSER_CHANNEL`、`BROWSER_EXECUTABLE`，或运行 `npx playwright install chromium`。

### Python 离线模型对照

`model/` 存放与前端共用参数和情景样本的 Python 参考模型（Python 3.12+，依赖见 `model/requirements.txt`）：

```sh
python -m pip install -r model/requirements.txt
python model/run_study.py            # 完整研究，结果写入 model/results/
python model/export_web_reference.py # 重新生成 src/scenarios.ts、tests/reference.json 等
python model/export_crosscheck.py    # 导出 24 组逐路径结果
npm run test:crosscheck              # 前端引擎与 Python 逐路径对照
cd model && python financing_study.py && python export_financing_crosscheck.py && cd ..
npm run test:financing-crosscheck    # 3.0 融资安排逐路径对照（44组）
```

`export_web_reference.py` 运行后用 `git diff` 检查，前端情景输入与参考路径应无变化。`model/expected/study_results.json` 是交付基准，可与新的 `model/results/study_results.json` 比较。

## 目录

- `src/engine.ts`：资金约束下的五批事件仿真。
- `src/workflow.ts`：规则、确认、证据、银行反馈及成员核对。
- `src/study.ts`、`src/worker.ts`：共同样本分析与历史匹配；`src/workerCode.ts` 为构建生成的计算线程代码。
- `src/scenarios.ts`：情景输入数据，由 `model/export_web_reference.py` 生成。
- `src/main.tsx`、`src/styles.css`：页面与交互。
- `tests/reference.json`：Python 参考路径与结果。
- `scripts/`：构建脚本与各项检查。
- `e2e/`：浏览器端交互、布局与离线文件测试。
- `model/`：Python 参考模型、交付基准与对照导出脚本。
- `docs/v3/`：3.0 研究记录、授信模式设计与创新性对照、开发记录。
- `CHANGELOG.md`、`VERIFICATION.md`、`PROJECT_HANDOFF.md`、`DEPLOY_CLOUDBASE.md`：版本差异、测试记录、工程交接与静态托管部署说明。
- `verification/`：参考模型副本、参考研究结果，以及最近一次运行生成的检查结果。
